# 00 — Delivery Plan

**Product:** Recurring Task Tracking, Pending Reports & Escalation Automation (Allo Innoware assignment)
**Platform:** Google Sheets + Google Apps Script (V8), bound to one spreadsheet
**Repo layout:** `specs/` (this) · `src/` (Apps Script source) · `test/` (local Node harness) · `dist/` (paste-ready bundle)

## 1. Objective

Show the full loop, fully automated, from a single spreadsheet:

```
task becomes due → employee acts → enters proof once → cycle closes and the next one is scheduled
        └── not done by cut-off → same-day manager email → manager acknowledges
                └── no acknowledgement / still not done → automatic leadership escalation
```

The test of quality: **simple for the employee, reliable for the manager, and silent unless something changes.**

## 3. Key design decisions (the short version)

| Decision | Choice | Why |
|---|---|---|
| Where the employee works | **One personal tab per employee** (`👤 Employee A`), generated by the system | They see only their own work, and the input cell sits on the same row as the task. No filters to break, no shared-view collisions. |
| How completion is captured | **Type the Ticket ID or the update text into the yellow cell and press Enter.** No checkbox, no second sheet. | It's one action, and the proof *is* the completion signal, so nobody can tick "done" without evidence. |
| Daily (WhatsApp) task | **Paste the update you posted into the yellow cell.** The text is stored as proof, and a one-tap "Share on WhatsApp" link is generated for the opposite flow (write first, then post). | Without a WhatsApp API this is the cheapest *verifiable* evidence: the manager can match the text against the group. Spec: `features/F04`. |
| Recurrence model | **Schedule-anchored slots** (`First Due + k × N days`). Interval tasks keep one open cycle at a time; the next one is created the moment the current one closes. Daily tasks get one cycle per working day. | Due dates never drift, whether work is done early or late. Late work does not create a pile of duplicate cycles. |
| Escalation timing | Reminder 2 h before cut-off → manager email 30 min after cut-off (same day) → leadership at **11:00 next working day if not acknowledged**, or **cut-off time next working day if still not done**. | Spec: `features/F07`. Each step gives the next person a realistic window, and nothing fires on non-working days. |
| No duplicates | Deterministic cycle IDs (`TaskID-yyyymmdd`), a per-cycle "sent at" stamp for each email type, a script lock around every write path, and the cycle saved right after each email | Running the engine repeatedly is safe. Spec: `features/F08`. |
| Testability | All logic takes an injected `ctx` (spreadsheet, clock, mailer). One test suite runs **both** inside Google Sheets (on a throw-away sandbox) and locally in Node. | We can prove behaviour at 18:29 and 18:31 without waiting a day. |

## 4. Acceptance criteria (definition of done)

1. `npm test` passes: the full in-sheet suite (Tests 1–8 and the robustness tests B01–B22) plus the Node-only checks.
2. `dist/Code.gs` is a single, paste-ready file. `Setup` builds every sheet on an empty spreadsheet.
3. Running the engine N times in a row creates no extra cycles, completions or emails.
4. Each assignment test (1–8) maps to a named automated test and to a manual demo step in `README.md`.

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Apps Script quotas (MailApp ~100/day on consumer accounts, 6 min/run) | Batched emails (one per recipient per event type per run), a quota check before sending, batch sheet I/O |
| Mock harness differs from real Apps Script | Strict mock (throws on unknown getters, on out-of-bounds ranges, on value/size mismatch); the same suite can be run inside Sheets from the menu |
| Sheets auto-parsing typed text (e.g. ticket `11-12-2026` becoming a date) | Input and ID cells are formatted as plain text (`@`) |
| Email link scanners "clicking" acknowledgement links | GET only shows a confirmation page; the acknowledgement needs a button press (POST via `google.script.run`) |
| Triggers silently stop | The dashboard shows "Engine last ran at …", so a stale time is visible to the manager |
| Timezone drift between script and sheet | Manifest pins `Asia/Kolkata`; Setup aligns the spreadsheet timezone to the script |
