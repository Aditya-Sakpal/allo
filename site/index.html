Recurring tasks that report themselves.

A Google Sheets and Apps Script system for Allo Innoware. Each employee closes a task by typing one thing into one cell. The manager hears about misses the same evening, and leadership only when the process itself has stalled. No duplicate work, no duplicate emails.

Download Code.gs appsscript.json Source & specs

One cell is the whole update.

Every employee has their own tab listing what needs action, when it is due, and what proof counts. When the work is done they type the portal Ticket ID, or paste the update they posted on WhatsApp, into the yellow cell and press Enter.

That single entry records who and when, closes the cycle, writes the audit log, refreshes the manager's dashboard and schedules the next due date. Nobody calculates dates, and nobody updates a second sheet.

Junk is refused with a reason on the same row: done, last week's ticket, or yesterday's update pasted again.

When something slips, the right person hears once.

The timing is configurable. These are the defaults and the reasoning behind them. Weekends and listed holidays are skipped, so a Friday miss is not escalated on Saturday.

  1. 16:00due day
    Reminder to the employeeTwo hours before the cut-off. Prevention is cheaper than escalation.
  2. 18:00due day
    Cut-offThe task turns overdue on every view.
  3. 18:30same day
    Manager alert emailLists every late task for that manager in one email, with a one-tap Acknowledge per task. The 30-minute grace absorbs someone finishing at 18:05.
  4. 11:00next working day
    Leadership, if the manager has not acknowledgedAt this point the process has failed, not just the task.
  5. 18:00next working day
    Leadership, if it is still not doneA full extra working day to fix it, even with an engaged manager.
  6. when closed
    One "resolved" noteCloses the loop for leadership. After that there are no reminders and no nagging.

The decisions that matter

The daily task's proof is the update itself

A WhatsApp post produces no ticket, and a "done" tick proves nothing. The employee pastes the message they posted, which is one paste of text they wrote anyway. It is stored with a timestamp, checked against yesterday's, and the manager can match it to the group. A share link covers the write-it-here-first habit.

The schedule is anchored, so it never drifts

Due dates are First Due + k × N days, whether work lands early or late. A very late completion records the slot it missed and opens the next future one, so one late piece of work never turns into a pile of duplicate tasks.

Running it twice is harmless

Cycle IDs are deterministic, completion requires an open cycle, every email type is stamped on the cycle the moment it sends, and a script lock serialises writes. A failed email is retried until it is delivered, then never again.

Acknowledgement is evidence, not a click

Email links are signed per task and only open a confirmation page, so a mail scanner can't acknowledge on the manager's behalf. Ticking is permanent; a note records what happens next. Leave or holidays are waived, with the reason logged.

Install in about five minutes

  1. Create a Google Sheet, then open Extensions → Apps Script.
  2. Replace Code.gs with the downloaded bundle. Show appsscript.json in Project Settings and replace it with this manifest, which pins the timezone to Asia/Kolkata.
  3. Run setupSystem and authorise. Every sheet is built and the four-employee demo is loaded. Reload the spreadsheet.
  4. Menu Task System → Admin → Install triggers. The engine then runs every 15 minutes and edits are processed instantly.
  5. Optional: Deploy → Web app for one-tap acknowledgement links. Add real emails in Team and Config and set EMAIL_MODE = LIVE.

Use Demo clock in the menu to walk a full day in a few minutes: alert at 18:31, ack deadline at 11:01, escalation at 18:01. Use "Back to real time" when you're done.

Proven with 30 tests that run inside the Sheet

Menu Task System → Automated tests runs the suite on a throw-away copy of the spreadsheet and writes PASS or FAIL with evidence to Test Results. The same suite runs locally with npm test, against a strict Apps Script mock.
